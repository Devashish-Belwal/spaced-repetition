1. Why is constructing query strings using `URLSearchParams` preferable over manual string concatenation in Next.js, and how does it prevent malformed URLs, broken parameters, and security vulnerabilities?

**Deep explanation:** Manually building URL query strings via string interpolation or concatenation (e.g., `` `/search?q=${query}&filter=${filter}` ``) is brittle and introduces significant security and parsing defects:
- **Automatic URL-Encoding vs. Delimiter Collisions:** When query values contain reserved URL characters (such as `&`, `=`, `?`, `#`, `/`), spaces, or multi-byte Unicode characters (e.g., emojis, accented letters, or international scripts), unencoded string interpolation corrupts the query structure. For example, if a user searches for `"c++ & rust"`, an unencoded query string `?q=c++ & rust` treats `&` as a parameter delimiter. Parsers interpret this as two distinct parameters: `q=c++ ` and `rust=`. Similarly, an unencoded `#` (hash) truncates the query string on the client, treating everything after it as an anchor/fragment identifier that never reaches the server.
- **Handling Delimiters and Encoding via `URLSearchParams`:** The WHATWG standard `URLSearchParams` interface automatically percent-encodes keys and values in accordance with RFC 3986 / the WHATWG URL standard. Characters like `&` become `%26`, spaces become `+` or `%20`, and Unicode codepoints are correctly encoded into UTF-8 percent-encoded bytes without requiring manual calls to `encodeURIComponent()`.
- **Preventing HTTP Parameter Pollution and Injection:** Unsanitized string concatenation can allow malicious or unintended inputs to inject extra parameters (HTTP Parameter Pollution, or HPP). If query parameters govern sensitive server operations (like authorization callbacks, redirect destinations, or database filters), injected parameters could override legitimate application parameters. Furthermore, if raw query strings are reflected into DOM attributes or client-rendered links without sanitization, unvalidated schemes like `javascript:` or unescaped quotes can lead to Cross-Site Scripting (XSS). Constructing parameters through `URLSearchParams` guarantees that special URL delimiter characters are treated strictly as data payloads rather than structural protocol separators.
- **Robust Value Coercion:** `URLSearchParams` provides predictable serialization for primitives, arrays, and objects via `.set()`, `.append()`, `.delete()`, `.get()`, and `.toString()`, eliminating subtle bugs such as trailing `?` or `&` when parameters are empty.

**Interview answer:** "`URLSearchParams` provides standards-compliant, automatic percent-encoding for reserved characters, spaces, and Unicode, preventing parameter splitting from `&` or query truncation from `#`. It prevents malformed URLs and HTTP parameter pollution while providing a clean, robust API that eliminates the subtle parsing and security risks of manual string concatenation."
