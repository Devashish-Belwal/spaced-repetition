1. How has the default `credentials` mode in the Fetch API evolved across browser specifications, and what are the practical implications for modern versus legacy codebases?

**Deep explanation:** The default value of the `credentials` property has a significant history that often surfaces in interview discussions and legacy codebase migrations:
- **The Original Specification (`"omit"`):** In the early WHATWG Fetch standard, the default `credentials` mode was `"omit"`. This was a major departure from the legacy `XMLHttpRequest` (XHR) API, which inherently attached same-origin cookies by default without requiring any configuration. Developers switching to early implementations of `fetch()` frequently encountered bugs where session cookies were unexpectedly excluded on same-origin requests unless they explicitly specified `{ credentials: 'same-origin' }`.
- **The Specification Revision (`"same-origin"`):** Recognizing that `"omit"` caused developer confusion and differed from standard browser navigation and XHR behavior, the WHATWG updated the Fetch specification around late 2017 to make `"same-origin"` the default mode.
- **Browser Adoption:** Major browsers adopted this change in 2018 (Google Chrome 68+, Mozilla Firefox 61+, Apple Safari 11.1+ / iOS 11.3+, and Microsoft Edge 18+). In modern runtimes, any same-origin `fetch('/api/data')` call automatically includes session cookies without manual intervention.
- **Practical Implications:**
  - In modern development, explicit configuration is only needed when deviating from same-origin defaults—either opting into cross-origin cookie sharing (`credentials: 'include'`) or deliberately stripping cookies for performance/caching/privacy (`credentials: 'omit'`).
  - In legacy systems, older web views, embedded runtime environments, or legacy polyfills (such as early versions of `whatwg-fetch`), assuming `"same-origin"` can cause silent authentication failures unless the polyfill has been updated or `{ credentials: 'same-origin' }` is passed defensively.

**Interview answer:** "The Fetch specification originally defaulted `credentials` to `\"omit\"`, meaning same-origin cookies were not sent unless explicitly configured. The spec was updated in 2017 to make `\"same-origin\"` the default—matching traditional `XMLHttpRequest` behavior across all modern browsers since 2018—while still safely omitting credentials on cross-origin requests by default."
