1. What are the three credentials modes in the Fetch API, and how do they govern the transmission of cookies and authentication data for same-origin and cross-origin requests?

**Deep explanation:** The Fetch API exposes the `credentials` property within the request configuration object (`RequestInit`) to control how browsers handle user credentials—specifically HTTP cookies, HTTP Basic/Digest authentication headers, and TLS client certificates. The three supported modes are:
- `"omit"`: Instructs the browser to never attach credentials to the request, regardless of whether it is same-origin or cross-origin. In addition, the browser ignores any `Set-Cookie` response headers returned by the server, preventing cookies from being stored. This mode is useful for public API calls, static assets, or privacy-sensitive requests where you want to ensure no identifying session tokens or ambient credentials leak.
- `"same-origin"`: The browser automatically attaches credentials and processes `Set-Cookie` response headers if and only if the target URL has the exact same origin (matching protocol, domain/host, and port) as the executing script. If the request is cross-origin, credentials are stripped completely, and received cookies are not saved.
- `"include"`: Directs the browser to transmit credentials on all requests—both same-origin and cross-origin. Incoming `Set-Cookie` response headers are also honored, provided the server responds with the appropriate Cross-Origin Resource Sharing (CORS) access control headers and the browser's cookie policies (e.g., `SameSite=None; Secure`, third-party cookie restrictions, or Storage Access API permissions) permit it.

**Interview answer:** "The Fetch API `credentials` option controls whether cookies, HTTP authentication, and TLS certificates are sent and received. The three modes are `\"omit\"` (never send or store credentials), `\"same-origin\"` (attach credentials only for requests to the exact same origin), and `\"include\"` (always send credentials across both same-origin and cross-origin requests, subject to CORS constraints)."
