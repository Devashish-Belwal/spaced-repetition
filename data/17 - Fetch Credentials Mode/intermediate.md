1. What are the strict CORS requirements and security constraints when executing cross-origin fetch requests with `credentials: 'include'`?

**Deep explanation:** When a frontend application makes a cross-origin request using `credentials: 'include'`, the browser attaches sensitive ambient credentials (such as session cookies). To prevent unauthorized cross-origin data exposure (e.g., Cross-Site Request Forgery or information disclosure attacks), the Fetch specification and CORS standard enforce strict response validation:
- **Explicit Credential Authorization:** The receiving server must explicitly authorize the inclusion of credentials by returning the response header `Access-Control-Allow-Credentials: true`. If this header is missing or set to `false`, the browser aborts the request lifecycle, triggers a CORS failure, and blocks client-side JavaScript from reading the response.
- **Disallowed Wildcard Origins:** When credentials are included, the server cannot return a wildcard origin (`Access-Control-Allow-Origin: *`). The `Access-Control-Allow-Origin` header must reflect the exact, specific origin of the requesting application (e.g., `Access-Control-Allow-Origin: https://app.example.com`). Combining `Access-Control-Allow-Credentials: true` with a wildcard origin is explicitly rejected by the browser.
- **Preflight (`OPTIONS`) Handling:** If the cross-origin request includes non-simple methods (such as `PUT`, `DELETE`, or `PATCH`) or custom headers (like `Content-Type: application/json`), the browser initiates a preflight `OPTIONS` request. The preflight check itself does not transmit cookies, but the preflight response from the server must also include `Access-Control-Allow-Credentials: true` alongside the matching `Access-Control-Allow-Origin` and allowed methods/headers before the browser proceeds with the actual credentialed request.
- **Modern Cookie Policies:** In addition to CORS headers, modern browsers enforce `SameSite` cookie restrictions. Cross-origin credential transmission requires cross-site cookies to be explicitly configured with `SameSite=None; Secure`, and respects emerging privacy sandboxing initiatives (such as Partitioned cookies / CHIPS and third-party cookie blocking).

**Interview answer:** "When using `credentials: 'include'` on cross-origin requests, the server must explicitly respond with `Access-Control-Allow-Credentials: true` and must provide an exact origin in `Access-Control-Allow-Origin` rather than the wildcard `*`. If either condition is violated, the browser blocks client-side JavaScript from reading the response due to CORS security rules."
