1. What is the purpose of the `cookie-parser` middleware in Express, and how does request handling differ when it is omitted?

**Deep explanation:** By default, Express does not automatically parse incoming HTTP `Cookie` request headers. When a client sends a request with cookies, Node's native HTTP server exposes them as a raw, serialized string on `req.headers.cookie` (e.g., `"sessionId=xyz789; theme=dark"`). Without middleware, `req.cookies` remains `undefined`, and accessing properties like `req.cookies.sessionId` results in a runtime `TypeError`. The `cookie-parser` middleware intercepts incoming HTTP requests, extracts the raw `Cookie` header string, parses the semicolon-delimited key-value pairs, and populates `req.cookies` with a clean JavaScript object. If no cookies are sent with the request, `cookie-parser` initializes `req.cookies` as an empty object (`{}`), eliminating null-reference issues and providing a standardized interface for subsequent middleware and route handlers.

**Interview answer:** "By default, Express leaves incoming cookies as an unparsed semicolon-delimited string in `req.headers.cookie`, leaving `req.cookies` undefined. The `cookie-parser` middleware intercepts requests, parses the raw `Cookie` header into key-value pairs, and populates `req.cookies` as a clean JavaScript object."
