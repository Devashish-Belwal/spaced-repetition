1. What is the precise purpose of the `'use client'` directive in Next.js App Router, and how does the serialization boundary operate?

**Deep explanation:** A common misconception is that `'use client'` tells React to render a component *exclusively* in the browser. In reality, components marked with `'use client'` are still pre-rendered to static HTML on the server during the initial Server-Side Rendering (SSR) pass to ensure fast First Contentful Paint (FCP) and SEO indexing.
- **The Client Boundary:** `'use client'` acts as a module-level boundary between the server and client module graphs. Adding `'use client'` at the top of a file designates that component and all modules imported beneath it into the client JavaScript bundle sent to the browser. It unlocks browser-specific APIs (`window`, `localStorage`), interactive React hooks (`useState`, `useEffect`, `useReducer`, `useRef`), and DOM event listeners (`onClick`, `onChange`).
- **The Serialization Boundary:** When a Server Component renders a Client Component, it passes data across a network/runtime serialization boundary using the React Server Component (RSC) wire format. Every prop passed across this boundary must be serializable into the RSC stream. Permitted types include primitives (strings, numbers, booleans, null), plain objects, arrays, Promises, BigInts, typed arrays, and React elements (JSX). Non-serializable values—such as functions, class instances, closures, and Node.js-specific objects (like database connection handles or file streams)—cannot cross the boundary and will trigger serialization errors.
- **The Children / Slot Pattern:** To prevent client bundle bloat and keep heavy dependencies on the server, developers should avoid importing Server Components into Client Components. Instead, pass Server Components as `children` or JSX slot props into the Client Component (`<ClientWrapper><ServerComponent /></ClientWrapper>`). In this pattern, the Server Component is evaluated on the server and passed as an already-serialized React element, preserving server execution while rendering seamlessly inside interactive client wrappers.

**Interview answer:** "`'use client'` marks the entry point boundary where React components and their imported subtrees transition from Server Components into the client JavaScript bundle, enabling hooks, event listeners, and browser APIs while still undergoing initial SSR. All props passed from Server Components to Client Components across this boundary must be serializable by the RSC protocol."
