1. What is Cross-Origin Resource Sharing (CORS), how does browser enforcement work, and how is basic origin access configured in Express with the `cors` package?

**Deep explanation:** Cross-Origin Resource Sharing (CORS) is a browser-enforced security mechanism built on top of the Same-Origin Policy (SOP). An origin is uniquely identified by the combination of its protocol (scheme), domain (host), and port (e.g., `https://example.com:443`). CORS does not protect backend servers from arbitrary HTTP clients (such as curl, Postman, or native mobile apps); rather, it prevents malicious websites running inside a user's browser from reading cross-origin HTTP responses or executing unauthorized actions on behalf of that user.

In an Express application, CORS headers are managed using the `cors` middleware package:
- **Allowing all origins:** Calling `app.use(cors())` or setting `{ origin: "*" }` sends the `Access-Control-Allow-Origin: *` response header. This grants any requesting web origin permission to read API responses. While suitable for public read-only APIs or early development, using wildcard origins in production is dangerous for private services and is explicitly prohibited when handling authenticated credentials.
- **Restricting to a specific origin:** Setting `{ origin: "http://localhost:3000" }` instructs the middleware to respond with `Access-Control-Allow-Origin: http://localhost:3000`. If an incoming browser request originates from any other domain, the browser intercepts the response, blocks frontend JavaScript from accessing the payload, and surfaces a CORS error in the developer console.
- **Production best practice:** Always avoid wildcard origins on endpoints dealing with sensitive or user-specific data. Explicitly declare trusted frontend origins matching your client applications.

**Interview answer:** "CORS is a browser-enforced security standard that restricts web applications from accessing resources located on a different protocol, domain, or port. In Express, the `cors` package configures this via `app.use(cors({ origin: 'http://localhost:3000' }))` to explicitly permit trusted client origins rather than leaving the API open with a wildcard `*`."
