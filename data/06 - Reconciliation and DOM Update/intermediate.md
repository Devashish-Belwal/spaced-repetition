1. What heuristic rules govern React's Virtual DOM diffing algorithm, and why are keys essential for reconciling list children?

**Deep explanation:** Finding the minimum number of edit operations to transform an arbitrary tree of $n$ nodes into another has an optimal theoretical complexity of $O(n^3)$. In an application with 1,000 UI elements, $10^9$ comparisons would freeze the JavaScript runtime. React implements an $O(n)$ heuristic diffing algorithm founded on two practical assumptions:

1. **Two elements of different types produce different trees:** If the root element type changes (e.g., from `<div>` to `<span>`, or from `<UserProfile>` to `<UserDashboard>`), React does not attempt to diff their child components. It tears down the old DOM subtree completely, invoking cleanup functions / unmount hooks (`useEffect` cleanup), and builds the new DOM tree from scratch. If elements share the same type (e.g., `<div className="before" />` vs `<div className="after" />`), React retains the underlying DOM node and mutates only changed attributes, styles, or event listeners.
2. **Keys provide identity stability across renders:** When reconciling a list of children, React traverses both lists of child elements simultaneously:
   - **Without keys (Index-based diffing):** React compares children sequentially by index. Appending an item to the end of a list works well because earlier indices match. However, prepending or reordering items shifts all subsequent indices; React fails to realize elements were merely moved and instead mutates every item, recreating or appending at the end. This leads to performance degradation and state leakage in stateful child components.
   - **With stable, unique keys:** Keys act as persistent identity identifiers. React builds an internal lookup map of keys from the previous tree, allowing it to detect insertions, deletions, and moves in $O(1)$ time. Instead of mutating or recreating nodes when a list is reordered, React executes minimal DOM operations like `container.insertBefore()` to reposition the existing DOM nodes.

**Interview answer:** "React achieves $O(n)$ diffing by assuming that elements of different types generate entirely different subtrees and that list items maintain identity across renders via `key` props. Keys allow React to match existing DOM nodes across renders, transforming costly node re-creations and mutations into efficient atomic DOM moves."
