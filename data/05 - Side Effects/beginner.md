1. What is a side effect in React, and why must the rendering phase of a component remain a pure function?

**Deep explanation:** In computer science and functional programming, a side effect is any operation that affects or interacts with the world outside the function being executed—such as modifying a global variable, mutating an argument, performing I/O, writing to local storage, or dispatching a network request. In React, a component's primary job is rendering: taking `props` and `state` as inputs and returning JSX describing the target UI. React expects this render phase to be a *pure calculation*—given the same inputs, it should return the exact same JSX without observable side effects. Keeping rendering pure is vital for modern React architecture:
- **Concurrent React:** React 18+ can start rendering an update, pause it to handle higher-priority user interactions, discard unfinished work, or re-render components in memory across multiple passes before committing changes to the DOM. If side effects (such as data fetching or subscriptions) occur during render, discarded or repeated render passes produce memory leaks, duplicate network requests, and race conditions.
- **Strict Mode:** In development, React Strict Mode intentionally double-invokes render functions, reducers, and state initializers to uncover hidden side effects and enforce render purity.
- **Predictability & Memoization:** Pure render logic is deterministic and easily optimized via memoization techniques (`React.memo`, `useMemo`), guaranteeing that the UI remains a predictable function of state.

**Interview answer:** "A side effect is any operation that reaches outside the pure calculation of a component's UI, such as network requests, DOM mutations, or timers. Component rendering must remain pure because Concurrent React may pause, abandon, or repeat render passes before committing changes to the DOM."
