1. What are the most common anti-patterns when managing side effects in React, and how can they be avoided?

**Deep explanation:** Misusing side effects—especially overusing `useEffect`—is one of the leading causes of bugs, performance degradation, and code complexity in React applications:
- **Transforming Data for Rendering in `useEffect`:** Fetching state, storing raw data, and using an effect to transform and store filtered/sorted data into a second state variable triggers cascading renders. Instead, compute derived values directly during render (e.g., `const visibleTodos = filterTodos(todos, filter);`), wrapping with `useMemo` only if computationally intensive.
- **Resetting State on Prop Changes via Effects:** Watching a prop (like `userId`) inside `useEffect` to clear form inputs causes a flash of stale state before the effect runs. The idiomatic solution is providing a unique `key` prop to the component (`<ProfileForm key={userId} />`), prompting React to cleanly unmount and reset component state automatically.
- **Chained Effects:** Setting State A in Effect 1, which triggers Effect 2 to set State B, creates unpredictable asynchronous chains. Workflows involving multiple coordinated updates should either be handled synchronously inside the initiating event handler or managed through a reducer.
- **Missing Cleanups:** Subscriptions, intervals, event listeners, or abortable fetch requests initiated inside `useEffect` must return a cleanup function. Omitting cleanups leads to memory leaks, duplicate active listeners, and updating state on unmounted components.

**Interview answer:** "Common anti-patterns include using `useEffect` to calculate derived state or reset forms on prop changes, chaining effects that trigger sequential updates, and omitting cleanup functions for timers or subscriptions. Calculating derived state synchronously during render and leveraging keys for state resets eliminates the vast majority of unnecessary effects."
