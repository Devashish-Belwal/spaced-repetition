1. What does the "use client" directive signify in React Server Components (RSC) and Next.js, and why is placing it at the root of a page component considered an anti-pattern?

**Deep explanation:** In React Server Components (RSC) and modern frameworks like Next.js App Router, `"use client"` does not instruct React to render a component exclusively in the browser. Instead, it defines a network and module boundary between the Server Component tree and the Client Component graph. When a file declares `"use client"`, that module and **all transitive modules and dependencies imported into it** are packaged into the client-side JavaScript bundle shipped to the browser.

Placing `"use client"` at the root of a page (such as in `page.tsx`) converts the entire sub-tree into Client Components. If a page contains 500 lines of mostly static UI (such as `<Hero />`, `<Features />`, and `<Footer />`) alongside a single interactive widget (such as `<InteractiveCounter />`), placing `"use client"` at the top forces the bundler to include all static components, their helper utilities, icons, and styling libraries into the browser bundle. This negates the primary architectural benefits of React Server Components: zero-bundle-size static components, direct access to server-side resources, and reduced browser memory footprints. The core architectural rule is to push `"use client"` as far down the component tree as possible—isolating client boundaries strictly to interactive leaf components.

**Interview answer:** `"use client" establishes a module boundary that bundles the component and all of its imported dependencies into the client JavaScript bundle. Placing it at the root of a page forces purely static components into the client bundle, negating the zero-bundle-size advantages of React Server Components.`
