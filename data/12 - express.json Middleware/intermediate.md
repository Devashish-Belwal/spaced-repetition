1. How does `express.json()` determine which requests to parse, and how does it handle malformed JSON payloads and mismatched `Content-Type` headers?

**Deep explanation:** `express.json()` is designed to operate selectively and fail predictably when handling incoming client payloads:
- **`Content-Type` matching:** `express.json()` evaluates the incoming request's `Content-Type` header using the `type-is` library. By default, it only processes requests with MIME types matching `application/json` (including vendor variants such as `application/*+json`). If the header is missing or does not match (e.g., `multipart/form-data`, `application/x-www-form-urlencoded`, or `text/plain`), `express.json()` completely skips body parsing, leaves `req.body` untouched (`undefined`), and passes control to the next middleware via `next()`.
- **Malformed JSON handling:** If `Content-Type` is `application/json` but the body contains invalid JSON (such as unquoted keys, single quotes, trailing commas, or truncated syntax), `JSON.parse()` throws a `SyntaxError`.
- **Error propagation:** `express.json()` intercepts this `SyntaxError`, decorates it with an HTTP status code (`status: 400`, `statusCode: 400`) and metadata (`type: 'entity.parse.failed'`), and passes it directly to Express's error-handling middleware via `next(err)`. Route handlers are bypassed, and if no custom error handler is defined, Express's default error handler returns a `400 Bad Request` HTTP response to the client.
- **The `strict` configuration:** By default, `strict: true` is enabled, which enforces RFC 7159 standards requiring the top-level value of the JSON document to be an object or an array. If a client sends a primitive JSON literal like `"hello"`, `123`, or `true`, the middleware rejects it with a `400 Bad Request` unless `{ strict: false }` is explicitly passed.

**Interview answer:** "`express.json()` inspects the `Content-Type` header and only parses payloads matching `application/json`, silently skipping non-matching content types. If the payload contains malformed JSON, it intercepts the thrown `SyntaxError` and forwards a `400 Bad Request` error to Express's error-handling pipeline."
