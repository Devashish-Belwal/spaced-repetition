1. What security vulnerabilities are associated with request body parsing, and how do `express.json()` configuration options like `limit` and `verify` mitigate them?

**Deep explanation:** Parsing incoming request bodies introduces critical security considerations around resource consumption and cryptographic validation:
- **Denial of Service (DoS) via memory exhaustion:** Because Node.js runs on a single-threaded event loop and allocates a finite V8 heap, accepting unbounded request streams allows malicious actors to send massive JSON payloads (e.g., hundreds of megabytes). Buffering and parsing these payloads consumes substantial memory and blocks the event loop, triggering Heap Out of Memory (OOM) process crashes or application unresponsiveness.
- **Payload size limits (`limit` option):** `express.json()` mitigates DoS risks through its `limit` option, which defaults to `'100kb'` (configurable via byte values or strings like `'1mb'`). If the incoming stream exceeds this threshold, the middleware immediately terminates stream consumption and passes a `413 Payload Too Large` error (`type: 'entity.too.large'`) to `next(err)`, protecting server memory before full deserialization occurs.
- **Webhook signature validation (`verify` option):** Many external webhook providers (such as Stripe, Shopify, or GitHub) require HMAC SHA-256 signature verification computed over the exact byte-for-byte raw request body. Once `JSON.parse()` converts the buffer into an object, differences in key ordering, whitespace, or unicode escaping prevent reconstructing the original raw byte stream. The `verify` option provides a callback `(req, res, buf, encoding) => {}` giving direct access to the raw `Buffer` `buf` before parsing, enabling developers to attach `req.rawBody = buf` for signature verification.
- **Additional options:** `inflate` (defaults to `true`, handling `gzip` and `deflate` compressed bodies while protecting against zip bombs) and `reviver` (a custom transformation function passed directly to `JSON.parse`).

**Interview answer:** "Unbounded body parsing exposes servers to Denial of Service attacks via memory exhaustion; `express.json()` protects against this using the `limit` option (defaulting to 100kb), which rejects oversized payloads with a `413 Payload Too Large`. Additionally, its `verify` option grants access to the raw buffer before JSON parsing, which is essential for validating cryptographic webhook signatures."
