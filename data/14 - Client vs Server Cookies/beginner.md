1. What is the difference between client-accessible cookies and `HttpOnly` cookies, and how are they accessed in client-side JavaScript versus backend environments like Express?

**Deep explanation:** Cookies are key-value pairs stored in the browser's internal cookie store and scoped to specific domains and paths. Standard cookies (created without the `HttpOnly` flag) are exposed to client-side scripts through the `document.cookie` DOM API, allowing JavaScript code to read, parse, and mutate them directly in the browser. In contrast, when a cookie is issued with the `HttpOnly` directive via the `Set-Cookie` HTTP response header, the browser explicitly restricts access from client-side execution contexts. Any attempt to inspect or modify an `HttpOnly` cookie via `document.cookie` yields nothing—the cookie remains invisible to all client-side scripts. However, `HttpOnly` does not prevent the cookie from participating in network traffic. On every subsequent HTTP request to matching origin, domain, and path parameters, the browser automatically serializes and attaches the cookie into the `Cookie` request header. On the server side, backend runtimes read this header directly; for example, in Node.js/Express with the `cookie-parser` middleware mounted, the server parses the raw header string into an accessible object at `req.cookies.cookieName` (or `req.signedCookies.cookieName` if cookie signing is enabled).

**Interview answer:** "Regular cookies can be read and modified by client-side JavaScript using `document.cookie`, whereas `HttpOnly` cookies are completely blocked from client scripts to protect sensitive data. Despite being invisible to client-side code, the browser still automatically transmits `HttpOnly` cookies in the `Cookie` request header, allowing backend frameworks like Express to access them via `req.cookies`."
